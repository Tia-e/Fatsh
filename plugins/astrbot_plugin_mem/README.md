# mem · 页 / 本 / 棚 三层记忆（v4，轮驱动）

全部逻辑落在插件内，**不读 sqlite**——因为 AstrBot 的 `conversations` 表只是"当前上下文窗口"（`max_turns=40`，每次写入砍最老一轮），不是聊天记录库。

## 存储：自建分片

```
data/mem_archive/<umo 哈希>/
  seg-0001.json   ← 装 page_turns 轮（1 轮 = 1 问 1 答）
  seg-0002.json
  ...
memory_store_v4.json   ← 页/本/棚 + 分片指针
```

- 每个分片装 **N 轮**，写满就关掉、**立刻新开下一个**，指针（`rec["hour"]["seq"] / file`）记着当前是哪个
- 关掉的那个分片马上喂给「页」整理
- 分片目录最多留 `archive_keep`（默认 10）个，超了删最早的

## 三层怎么滚

```
每 N 轮（默认 40）        → 整理「页」：重写这一页，冻结页只作参考
页被整理 5 次             → 整理「本」：吸当前页 → 页冻结、开新页
本被整理 5 次             → 整理「棚」：吸当前本 → 本冻结、开新本
```

- 存储永远只有 **页 2 格 / 本 2 格 / 棚 1 份**（当前 + 冻结）
- 上限：页 20 条、本 12 条、棚 8 条（都是"上限"不是目标）
- 注入只带当前页/当前本/棚；冻结的只做整理参考

## 条目格式

```json
{"content":"第一人称一句话，≤40字","type":"who|like|deal|rel","importance":1-5}
```

- **没有 id**：批次编号在重写页面时会被模型乱编（见过的 h1…/n1… 就是模型自己起的），所以不存 id，靠内容前 20 字去重
- **importance 决定顺序**：存储、注入、`/mem show` 一律按 importance 5→1 排序；超过上限时丢 importance 最低的
- 注入时只带 importance 最高的前 N 条（`inject.hour_items`）

## 为什么 40 轮

实测这轮对话 **≈167 tokens/轮**（60-70 字/轮），16k 减去固定系统开销（~3k）后：

```
16k 全用 ≈ 77 轮 ｜ 66% ≈ 45 轮 ｜ 一半 ≈ 30 轮
```

默认取 40 轮 ≈ 6.7k tokens，正好是 16k 的 **66%**，也和内核 `max_turns=40` 对齐。换 ctx 就改这个数。

## 指令

```
/mem                 状态（页几/几十条、本页轮数、本/棚进度、分片数）
/mem on|off          开关
/mem show            看现在会注入的记忆
/mem clear           清本会话的页/本/棚（分片保留，可用 gen 重新吸）
/mem page 0-100      每页多少轮（默认 40；0 = 不自动分页，只在 gen 时整理）
/mem gen 0-10        拿最近 N 个分片整理（0 = 全部；不够就按实际数量，不报错）
```

只有白名单 QQ 可用。

## 兜底

聊到 39 轮就断了怎么办：**空闲 30 分钟且攒了 ≥10 轮**时，自动提前关分片并整理（`idle_seconds` / `idle_min_turns` 可调）。

## 配置 `data/memory_config.json`

| 字段 | 默认 | 说明 |
|---|---|---|
| `page_turns` | 40 | 每页轮数（0 = 关闭自动分页） |
| `book_pages` | 5 | 几次页整理 → 一次本整理 |
| `profile_books` | 5 | 几次本整理 → 一次棚整理 |
| `archive_keep` | 10 | 分片目录最多留几个 |
| `idle_seconds` / `idle_min_turns` | 1800 / 10 | 空闲兜底 |
| `keep_pages` | 2 | 页/本各留 2 格 |
| `max_items` | 20/12/8 | 页/本/棚上限 |
| `inject` | 20/12/8 | 注入条数 |

## 旧数据

`memory_store_v3.json` 会在首次加载时自动迁移（页/本各取最后 2 页，棚照搬），迁移后不再读 v3。
